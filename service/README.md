# Worker service

Run `npx tsc --noEmit -p .` and `npx vitest run` here; dependencies are already installed. Tests use in-memory SQLite and fake fetch; they never contact YouCam. `better-sqlite3` is test-only, pinned to a version with Node 20 prebuilt binaries. Root contracts and dependencies are unchanged.

`wrangler.toml` is a configuration skeleton, not a provisioned deployment. An integrator must bind an existing D1 database as `DB`, apply migrations `0001.sql` through `0004.sql` in order from `migrations/`, and supply server secrets separately. `IP_HASH_SECRET` must be a strong random secret, stable across requests; only the trusted Cloudflare `CF-Connecting-IP` header is used. Missing trusted IP or salt fails closed. Do not forward this handler behind a proxy that lets clients forge that header. No credentials or database identifiers are included. The local dev/e2e harness uses Miniflare and never deploys.

`YOUCAM_MODE=mock` selects synthetic fixtures and an isolated mock quota ledger, leaving the live allowance untouched. Multipart metadata may additionally contain `mockFixture` with `success`, `error_no_face`, `error_src_face_too_small`, or `timeout`; this hook is ignored in live mode. Fixtures contain synthetic numbers and run2 masks from a synthetic AI face, no photographs. `YOUCAM_MODE=live` requires `YOUCAM_API_KEY` and never falls back. `judgeCode` matching server `JUDGE_CODE` chooses the judge pool; matching `DEV_CODE` chooses dev; otherwise public. Leave access codes unset to disable those privileged pools.

D1 stores accounting, salted IP hashes, session-scoped image digests, and job state, never image bytes, image URLs, or scores. Images are held only while uploading. Observations are isolate-local, logically expire 30 minutes after job creation, and are evicted on the next request; garbage collection or isolate restart may remove them sooner. GET after expiry or result loss returns `not_found`. DELETE `/api/analyses/:id` immediately removes in-memory observations and records a durable privacy tombstone. It returns 200 with local/provider cleanup status. Repeated DELETE retries pending/failed cleanup; never-existing IDs return the uniform `ApiError` 404. Subsequent GET returns 404. In-flight polls cannot expose deleted observations. Non-terminal reservations become abandoned: units stay held while concurrency is freed. The browser sends DELETE with keepalive on End session, pagehide, expiry, and when replacing a job. Browser shutdown delivery is best-effort; the 30-minute expiry remains the backstop. Accounting persists to protect the budget, including after expiry. Job IDs are random bearer capabilities; do not log or share them.

Poll at ten-second intervals. Pending timeouts retain the provider task ID and reservation; subsequent GET resumes the same task. Definitive provider failure releases units; success commits once. Ambiguous task-submission failures retain a reservation even if no task ID was received. They require manual provider-console reconciliation and must never be automatically released or recreated. Expiring a session does not release uncertain reservations. Failed attempts count toward the per-IP daily cap. UTC defines the quota day. The three live pools total 990 units (judge 450, public 180, dev 360).

The live adapter follows the confirmed file/upload/task schemas, reads results.output, ignores unknown concern types and overall-score entries, and maps string provider errors. Uploads use provider instructions without API authorization. Local DELETE also attempts provider task deletion, without blocking local deletion on failure. Higher raw_score and ui_score mean healthier skin (1–100); prefer raw_score for logic and label ui_score as the calibrated provider display score. No severity thresholds are used; Breakout Log records appearance without determining causes. Provider retention is documented in ../docs/PRIVACY.md.

Contract workarounds: reservation IDs are also job IDs because `BudgetGuard` has no job-link method. The frozen adapter has no fixture argument, so the mock-only metadata hook constructs a fixture adapter inside the Worker. The frozen GET route has no session credential; random job IDs provide access. These choices do not modify contracts.

## Local mock flow and e2e

Run `npm run dev` in service; in another terminal run `npm run dev` in web. Vite proxies `/api` to port 8787. The service command bundles the real worker into Miniflare, creates ephemeral local D1, applies migrations 0001 through 0004 in order, generates a per-process privacy salt in memory, and blocks outbound fetches. No cloud account or provider credentials are needed.

Run `cd service && npm run test:e2e` for the Miniflare/workerd + local D1 suite. It generates a valid solid-color JPEG in memory, uses the real web API client, waits the real ten-second polling interval, decodes the returned PNG masks, builds and compares two Breakout Log entries, renders through jsdom, validates a validated appearance-log export, checks severe-symptom referral, and verifies DELETE/GET/second DELETE. Provider task deletion success/failure runs through the real worker with intercepted outbound fetches and seeded task rows; no paid task is submitted. Nothing persists after disposal. Local tests, development, and deployment use compatibility date `2026-07-30`.


The legacy `smoke:live` step (`s4-live`) is exhausted and must not be run. The fixture now contains the URL-redacted Breakout Log run2 response, normalized in offline tests. Run `cd service && npm test` for all service and shared tests, or `cd service && npm test -- ../tests/shared` for only the shared log/region suite. Shared tests resolve Vitest from the existing service installation.

## Breakout Log v2

Requests use acne, redness, texture, and skin_type (9 units). Only the first three produce scored observations. Skin type produces whole/T/U labels verbatim. LiveAdapter fetches only acne, redness, T-zone and U-zone PNG masks with HTTPS, a 10-second timeout and a 512-KB limit per mask. Individual mask failures are tolerated. Provider URLs never appear in normalized output. Results, labels and masks logically expire after 30 minutes; physical eviction across idle isolates may be lazy. D1 stores accounting, tombstones and server-only cleanup handles/status. Mock masks are real run2 outputs from a synthetic AI face, Kai spike run2, bundled as base64.

Both `smoke:live` and `smoke:breakout` are disabled. Direct provider analysis bypasses D1 accounting and can consume the judge reserve. Development analysis must go through the worker with the dev code so it uses the dev pool. The one seeded 9-unit spent dev reservation conservatively covers the 4-unit difference between the D1 allowance of 990 and the last recorded provider balance of 986.

Run `MOCK=1 OUT_DIR=/tmp/breakout-checkpoint npm run checkpoint:breakout` for the fully synthetic checkpoint. It makes no provider or account requests. Replace the local-only D1 ID in `wrangler.toml` with the existing database ID during release preparation; this repository does not provision an account resource.
